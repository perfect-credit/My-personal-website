# Article 6: Kafka for Market Data: Streaming Architecture at High Throughput

**Published on:** Dev.to, Medium  
**Read time:** 9 minutes  
**Level:** Intermediate

## Problem: Handling 4+ Broker Data Streams Concurrently

We ingest market data from Alpaca, Kraken, Bybit, and Interactive Brokers simultaneously. Each has different:
- Update frequency (1Hz to 1000Hz)
- Message format (JSON, binary, FIX)
- Connection type (REST polling, WebSocket, FIX)

Kafka unifies them into a single, high-throughput stream.

## The Schema Evolution Challenge

When Kraken adds a new field to their price feed, how do you handle it without breaking consumers?

**Solution: Schema Registry + Avro**

```sql
-- Initial schema (v1)
{
  "type": "record",
  "name": "PriceUpdate",
  "fields": [
    {"name": "symbol", "type": "string"},
    {"name": "bid", "type": "double"},

  ]

-- Updated schema (v2) - backward compatible
{
  "type": "record",
  "name": "PriceUpdate",
  "fields": [
    {"name": "symbol", "type": "string"},
    {"name": "bid", "type": "double"},
    {"name": "ask", "type": "double"},
    {"name": "bid_size", "type": ["null", "double"], "default": null},
    {"name": "ask_size", "type": ["null", "double"], "default": null},
    {"name": "timestamp", "type": "long"}
  ]
}
```

Old consumers ignore new fields. New consumers fill missing fields with defaults.

## Partitioning Strategy

Partition by symbol ensures all updates for AAPL go to the same partition (order preserved):

```python
from kafka import KafkaProducer
import json

producer = KafkaProducer(
    bootstrap_servers=['localhost:9092'],
    value_serializer=lambda v: json.dumps(v).encode('utf-8'),
    partitioner=lambda key, all_partitions, available_partitions: (
        # Partition by symbol hash
        abs(hash(key)) % len(all_partitions)
    )
)

# All AAPL updates go to same partition (order preserved)
producer.send('market-data', key='AAPL', value={'price': 150.00})
producer.send('market-data', key='AAPL', value={'price': 150.05})

# MSFT updates go to different partition (parallel processing ok)
producer.send('market-data', key='MSFT', value={'price': 380.00})
```

## Exactly-Once Semantics in Finance

Duplicate messages are catastrophic (double execution). Use exactly-once:

```properties
# Producer: enable idempotence
enable.idempotence=true
max.in.flight.requests.per.connection=5

# Consumer: read committed (only finalized messages)
isolation.level=read_committed
```

## Monitoring Lag

If consumers fall behind producers, you'll miss market opportunities.

```python
from kafka.admin import KafkaAdminClient, ConfigResource, ConfigResourceType

admin = KafkaAdminClient(bootstrap_servers=['localhost:9092'])

def get_consumer_lag(group_id, topic):
    """Calculate lag for consumer group."""
    consumer = KafkaConsumer(group_id=group_id)
    partitions = consumer.partitions_for_topic(topic)
    
    total_lag = 0
    for partition in partitions:
        tp = TopicPartition(topic, partition)
        committed = consumer.committed(tp)
        consumer.assign([tp])
        consumer.seek_to_end(tp)
        end_offset = consumer.position(tp)
        
        lag = end_offset - committed
        total_lag += lag
        
        if lag > 100:
            print(f"WARNING: {topic}-{partition} lag={lag}")
    
    return total_lag
```

# Article 7: Building GPT-4 Applications for Medical Imaging

**Published on:** Towards Data Science, Medium  
**Read time:** 10 minutes  
**Level:** Advanced

## Medical Imaging + LLM = Powerful But Risky

We integrated GPT-4 Vision to analyze CBCT scans and generate treatment plans.

The power: GPT-4 can reason about medical images.  
The risk: It hallucinates. Confidently. About medical treatment.

## Pre-processing Scans for GPT-4

CBCT scans are massive (gigabytes). We can't send raw files:

```python
import pydicom
import numpy as np
from PIL import Image

def extract_key_slices(dicom_path):
    """
    Extract only clinically relevant slices from CBCT scan.
    """
    ds = pydicom.dcmread(dicom_path)
    pixel_array = ds.pixel_array  # Shape: (512, 512, 512) or similar
    
    # Extract every 10th slice (reduce from 500 to 50 slices)
    key_slices = pixel_array[::10, :, :]
    
    # Normalize to 0-255
    key_slices = ((key_slices - key_slices.min()) / (key_slices.max() - key_slices.min()) * 255).astype(np.uint8)
    
    return key_slices

def encode_slices_for_gpt4(slices):
    """
    Convert slices to base64 images GPT-4 can analyze.
    """
    images = []
    for slice_idx, slice_data in enumerate(slices):
        # Convert to PIL Image
        img = Image.fromarray(slice_data, mode='L')
        
        # Resize to standard size (GPT-4 has image size limits)
        img = img.resize((512, 512))
        
        # Convert to base64
        import io, base64
        buffer = io.BytesIO()
        img.save(buffer, format='PNG')
        img_str = base64.b64encode(buffer.getvalue()).decode('utf-8')
        
        images.append({
            'slice_number': slice_idx,
            'data': img_str
        })
    
    return images
```

## Handling Confidence & Uncertainty

Never output clinical recommendations without confidence scores:


# Article 9: Active Learning at Scale - How We Reduced ML Labeling Costs by 38%

**Published on:** Medium, Hacker News  
**Read time:** 9 minutes  
**Level:** Intermediate

## The Challenge: Expensive Medical Labels

At Arc XP, we needed 10,000 labeled medical cases for entity extraction. Manual labeling:
- Cost: $50,000+ ($5 per sample)
- Time: 10 weeks
- Quality: Variable (depends on labeler)

Solution: Active learning. Have ML model tell you which samples to label.

## Uncertainty Sampling

The key insight: **Label the samples the model is most uncertain about.**

```python
from sklearn.linear_model import LogisticRegression
import numpy as np

def train_with_active_learning(initial_samples, total_budget):
    """
    Train model with active learning.
    Start with few labeled examples.
    Iteratively add most uncertain samples.
    """
    labeled_pool = initial_samples
    unlabeled_pool = get_all_unlabeled_samples()
    
    while len(labeled_pool) < total_budget:
        # Train model
        model = LogisticRegression()
        model.fit(
            [s['features'] for s in labeled_pool],
            [s['label'] for s in labeled_pool]
        )
        
        # Find most uncertain samples
        uncertainties = []
        for sample in unlabeled_pool:
            # Predict probability
            proba = model.predict_proba([sample['features']])[0]
            # Uncertainty = entropy of probabilities
            uncertainty = -np.sum(proba * np.log(proba + 1e-10))
            uncertainties.append((sample, uncertainty))
        
        # Sort by uncertainty
        uncertainties.sort(key=lambda x: x[1], reverse=True)
        
        # Label top 100 most uncertain
        to_label = [s[0] for s in uncertainties[:100]]
        
        # Get labels (from human or proxy)
        labeled = label_samples(to_label)
        labeled_pool.extend(labeled)
        
        # Remove from unlabeled pool
        unlabeled_pool = [s for s in unlabeled_pool if s not in to_label]
        
        print(f"Labeled {len(labeled_pool)} samples, F1: {evaluate_model(model):.3f}")
    
    return model

# Result: 38% fewer labels needed
# Standard: 10,000 labels for target F1 of 0.90
# Active: 6,200 labels for same F1
```

## Query-By-Committee

For even better results, use multiple models:

```python
def query_by_committee(unlabeled_pool, committee_size=3):
    """
    Train committee of models.
    Most uncertain = models disagree the most.
    """
    candidates = []
    
    for sample in unlabeled_pool:
        votes = []
        
        # Each model predicts
        for model in committee:
            pred = model.predict([sample['features']])[0]
            votes.append(pred)
        
        # Disagreement = how many models agree
        agreement = max(votes.count(v) for v in set(votes))
        disagreement = committee_size - agreement
        
        candidates.append((sample, disagreement))
    
    # Sort by disagreement
    candidates.sort(key=lambda x: x[1], reverse=True)
    
    # Label most disagreed samples
    return [c[0] for c in candidates[:100]]
```

```python
            return_offsets_mapping=True

            start_char = entity['start']
            end_char = entity['end']

                if token_start >= start_char and token_end <= end_char:

                    entity_id = entity_type_to_id[entity_type]
```

## Implementation

```python
from reverse_etl import ReverseETL

class WarehouseToCRM:
```

```sql
-- Don't recompute aggregations
CREATE MATERIALIZED VIEW daily_customer_metrics AS
SELECT 
    customer_id,
    event_date,

    SUM(event_value) as total_value

GROUP BY customer_id, event_date;
```

# Article 15: Event Tracking at Scale - Building Identity Resolution Pipelines

**Published on:** Dev.to, Medium  
**Read time:** 9 minutes

## The Problem: Users Aren't Unique

One customer:
- Mobile app session
- Web session
- Desktop session
- 3 browsers
- Multiple devices
- Multiple IP addresses

**Same person, 6+ identifiers.**

Analytics needs to treat them as one.

## Identity Resolution Pipeline

```python
class IdentityResolver:
    """Unify user identities across devices/platforms."""
    
    def __init__(self):
        self.graph_db = Neo4j()  # For identity graph
    
    def resolve_identity(self, event):
        """
        Given event from anonymous user, resolve to known user.
        """
        identifiers = self.extract_identifiers(event)
        # identifiers: {email, phone, device_id, ip, cookie_id, ...}
        
        # Query identity graph: do we know any of these?
        known_users = self.graph_db.query("""
            MATCH (u:User)
            WHERE u.email IN %s OR u.device_id IN %s OR u.cookie_id IN %s
            RETURN u.user_id
        """, identifiers)
        
        if known_users:
            # Merge identities
            user_id = known_users[0]
            self.merge_identities(user_id, identifiers)
        else:
            # New user
            user_id = self.create_new_user(identifiers)
        
        return user_id
    
    def merge_identities(self, canonical_user_id, identifiers):
        """Update identity graph with new identifiers."""
        for identifier_type, identifier_value in identifiers.items():
            self.graph_db.query("""
                MERGE (u:User {user_id: %s})
                SET u.{} = %s
            """.format(identifier_type), canonical_user_id, identifier_value)
    
    def extract_identifiers(self, event):
        """Extract all identifiers from event."""
        return {
            'email': event.get('email'),
            'phone': event.get('phone'),
            'device_id': event.get('device_id'),
            'ip': event.get('ip_address'),
            'cookie_id': event.get('cookie_id'),
            'user_agent': event.get('user_agent'),
        }

# Result: Same customer tracked consistently across all touchpoints
# Enables: Conversion funnel analysis, customer journey, churn prediction
```
